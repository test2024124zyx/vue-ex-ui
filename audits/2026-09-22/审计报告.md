## 已确认问题

### AUD-01：共享焦点圈闭把 fieldset 内的禁用控件当成 Tab 目标

- 类型：交互/可访问性。确认状态：已在 Chromium、Firefox、WebKit 生产产物复现。严重性：高（特定布局的键盘操作阻断）。修复优先级：P1。
- 影响：1.0.1 的 Modal、Dialog、Drawer 已逐一确认；其他 `useOverlay` 消费组件属于待回归范围，不把它们全部列为已复现。
- 对应要求：R07；APG 的模态 Tab 循环；候选 WCAG 2.2 的 2.1.1/2.4.3。
- 前置：弹层内容首部含 `<fieldset disabled><input></fieldset>`，后面两个可用按钮。运行 `node audits/2026-09-22/browser-run.mjs`，查看 `FOCUS-*`。
- 最小步骤：打开弹层 → 聚焦最后一个可用按钮 → 按 Tab。预期：回到第一个可用按钮。实际：焦点仍停在最后一个按钮，重复 Tab 不能继续循环。
- 证据：`browser/results.json`，`browser/FOCUS-modal.png`、`FOCUS-dialog.png`、`FOCUS-drawer.png`。对照：把禁用状态改为 input 自身 `disabled` 后，循环成功，见 `browser/followup.json`。
- 根因：[overlay-manager.ts:10](../../src/composables/overlay-manager.ts#L10) 的 `isVisibleFocusable` 只检查自身 `disabled` 属性，遗漏原生 fieldset 继承禁用；第 243–252 行拦截默认 Tab 后对不可聚焦目标调用 focus，导致位置不变。
- 触发链：`useOverlay` → `createFocusTrap` → `getFocusableElements` → 错误目标。
- 建议：按实际 HTML 禁用语义筛选（包含 `:disabled`，正确保留 legend 例外），同时验证自动聚焦和 Tab 循环。
- 回归/验收：三个已确认组件中，Tab/Shift+Tab、普通 disabled、禁用 fieldset、legend 内允许控件和 Teleport 子面板都导航正确；关闭恢复焦点；不增加全局监听残留。
- 未验证：屏幕阅读器、真实触摸设备、所有 Overlay 消费路径。

### AUD-02：表单写入依赖 Array.at，违背已声明的最低浏览器范围

- 类型：兼容性/核心 API。确认状态：已复现缺失能力故障；历史浏览器整机运行未执行。严重性：高（基础字段写入和重置抛异常）。优先级：P1。

1. **深层 HTML 的健壮性边界已观察到，安全影响尚未定级。** Node 发布产物消毒 32/128/512/1024/2048 层返回；4096 层、45,062 bytes 的合法嵌套输入抛 `RangeError: Maximum call stack size exceeded`，约 11.4ms。根因候选为 `src/utils/sanitize.ts:168` 的递归及序列化链。未给出可承诺最大深度，未证明持久服务不可用或浏览器全页面崩溃；不称其为高危 DoS。建议明确输入深度/资源边界并提供可控拒绝路径。原始输入生成规则和结果见 `node-probes.mjs/json`。
